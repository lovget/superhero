# SDD — Описание дизайна

## 1. Введение

### 1.1 Назначение

Программа «Калькулятор уровня супергероя» предназначена для определения уровня пользователя на основе введённых физических показателей: роста, веса, возраста, количества подтягиваний и продолжительности сна.

### 1.2 Область применения

Приложение разработано на языке Java с использованием графического интерфейса Swing. Архитектура программы построена по паттерну MVC с использованием активной модели и интерфейса ModelListener.

## 2. Обзор дизайна

Программа состоит из следующих основных компонентов:

- `SuperheroModel` — модель данных и основная бизнес-логика;
- `MainView` — главное окно приложения и отображение результатов;
- `InputDialog` — окно ввода исходных данных;
- `SuperheroController` — обработка действий пользователя и передача данных в модель;
- `Main` — точка входа в приложение.

Взаимодействие компонентов организовано по паттерну MVC.

## 3. Проектные представления

### 3.1 Контекстное представление

Пользователь взаимодействует с графическим интерфейсом `MainView`. Для ввода данных открывается `InputDialog`. Введённые значения передаются через `SuperheroController` в `SuperheroModel`, где выполняется проверка данных и расчёт уровня супергероя. После изменения состояния модель уведомляет `MainView` через `ModelListener`.

### 3.2 Логическое представление

Класс `SuperheroModel` хранит рост, вес, возраст, количество подтягиваний, продолжительность сна, рассчитанный уровень и состояние наличия данных.

Класс `MainView` содержит элементы графического интерфейса и отображает значения, полученные из модели.

Класс `InputDialog` содержит поля для ввода исходных данных пользователя.

Класс `SuperheroController` связывает представление и модель, обрабатывает ввод пользователя и передаёт данные в `SuperheroModel`.

Интерфейс `ModelListener` используется для уведомления представления об изменении состояния модели.

### 3.3 Представление взаимодействия

Основной сценарий работы приложения:

1. Класс `Main` создаёт `SuperheroModel`, `SuperheroController` и `MainView`.
2. Пользователь нажимает кнопку «Ввести данные».
3. `MainView` обращается к `SuperheroController`.
4. Контроллер открывает `InputDialog`.
5. Пользователь вводит рост, вес, возраст, количество подтягиваний и продолжительность сна.
6. `SuperheroController` преобразует введённые значения и передаёт их в модель.
7. `SuperheroModel` проверяет корректность данных и выполняет расчёт уровня.
8. Модель уведомляет зарегистрированные объекты через `ModelListener`.
9. `MainView` обновляет отображаемые значения.

### 3.4 Физическое представление

Исходный код проекта организован по пакетам:

- `superhero.model` — модель;
- `superhero.view` — графический интерфейс;
- `superhero.controller` — контроллер;
- `superhero` — класс `Main`.

Такое разделение позволяет отделить бизнес-логику от графического интерфейса и обработки пользовательских действий.

## 4. Основные проектные решения

### 4.1 Архитектурный паттерн

Для приложения выбран паттерн MVC. `SuperheroModel` отвечает за состояние и расчёты, `MainView` — за отображение информации, а `SuperheroController` — за обработку действий пользователя.

### 4.2 Активная модель

Модель реализует активное уведомление представления. Для этого используется интерфейс `ModelListener`. После изменения данных `SuperheroModel` вызывает `notifyListeners()`, после чего `MainView` обновляет информацию на экране.

### 4.3 Проверка данных

Проверка входных данных выполняется в `SuperheroModel` методом `validateData()`. При обнаружении некорректного значения генерируется `IllegalArgumentException`. Ошибка передаётся контроллеру и отображается пользователю.

### 4.4 Графический интерфейс

Для создания пользовательского интерфейса используется библиотека Swing. Главное окно реализовано в классе `MainView`, а ввод исходных данных выполняется через отдельное окно `InputDialog`.

## 5. Заключение

Разработанная архитектура разделяет данные, пользовательский интерфейс и обработку действий пользователя. Использование MVC и `ModelListener` обеспечивает автоматическое обновление представления после изменения состояния модели и упрощает дальнейшее развитие приложения.
